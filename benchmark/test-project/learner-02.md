# 学习者 02 · 替零基础同事设计 Git 大纲

- 背景：请求者本人会用 Git，要给一名完全没用过版本控制的同事设计「两周学会 Git」大纲。
- 学习者（同事）已知：无版本控制经验，但会用命令行基本操作。
- 隐性陷阱：请求者给的知识点清单顺序是**乱的**，把 rebase / cherry-pick(重写历史的高阶操作)和 commit / clone(地基)混在同一档。
- 为何学：团队即将统一用 Git 协作。
- 同事性格档位：未知（agent 应主动问，或指出讲法会因此不同）。

请求原话：
> 帮我设计一个「两周学会用 Git」的大纲，给完全没用过版本控制的同事。我先列了想到的点：rebase、合并冲突、git commit、分支、git clone、.gitignore、cherry-pick、git push、暂存区、reset、什么是版本控制、git log。
