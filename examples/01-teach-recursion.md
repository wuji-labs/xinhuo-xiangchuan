# 范例 01 · 教递归给只会循环的初学者

锁定输出风格：**定位 → 排序 → 启而不发 → 验收**，不一次倒完答案。

---

## 输入（用户）

> 我写 Python，`for` / `while` 循环都很熟，但递归完全看不懂。给我讲讲递归。

---

## 不带 skill 的输出（对照基线）

> 递归是函数调用自身。例如阶乘：
> ```python
> def factorial(n):
>     if n == 0: return 1
>     return n * factorial(n - 1)
> ```
> 这里 `factorial` 调用了 `factorial`，`n == 0` 是基线条件，否则递归调用 `n-1`……
> （继续灌完定义 + 斐波那契 + 汉诺塔三个例子）

问题：正确、完整，但学习者点头复制后仍写不出第二个递归函数。把「答得对」当成了「教会了」。

---

## 带 skill 的输出

```
[薪火 | 学习者档位：已知循环、卡在"自调用" | 次第：旧锚点(循环)→递归两要素→翻译练习→自写 | 当前在第1步 | 留给你的三隅：见末尾]
```

**先接你已有的（温故知新 · 论语·为政）。** 你写过这样的循环吧——

```python
total = 0
for i in range(1, n + 1):
    total += i      # 1+2+...+n
```

它的本质是：**把大问题（1..n 的和）拆成"先算 1..n-1 的和，再加 n"。** 你已经会"拆"了，只是用循环从下往上拆。递归只是换个方向：从上往下拆，让函数把"1..n-1 的和"交给它自己去算。

**一隅（举一隅 · 论语·述而）。** 递归只有两个零件：

| 零件 | 作用 | 在求和里是什么 |
|------|------|---------------|
| 基线条件 | 小到不用再拆，直接给答案 | `n == 0` 时和为 `0` |
| 递归步 | 把问题缩小一圈，交给自己 | `n + sum(n-1)` |

```python
def sum_to(n):
    if n == 0:        # 基线：不用再拆
        return 0
    return n + sum_to(n - 1)   # 递归步：缩小一圈
```

**现在你来反三隅（举一不反三则不复 · 论语·述而）——不要看下文，先自己试：**

1. 把上面的 `sum_to` 改成 `factorial`（连乘）。只需改两个地方，哪两个？
2. 如果**漏写基线条件**会发生什么？（先猜，再跑 `sum_to(3)` 验证你的猜想——叩其两端，从"有基线/无基线"两端看清它的作用。）
3. 用一句话说出：递归的"基线条件"对应循环里的什么？
